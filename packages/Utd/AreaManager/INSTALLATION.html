⚙️ خطوات التثبيت

الطريقة 1: باستخدام Composer (الموصى بها)

1 تثبيت الحزمة عبر Composer:
composer require utd/area-manager
2 تسجيل في PackageHelper (إضافة في app/Support/PackageHelper.php):
use Utd\AreaManager\Entities\AreaManager; private static array $packages = [ // ... other packages 'areaManager' => AreaManager::class, ];
3 تشغيل Migrations:
php artisan migrate
4 مسح الـ Cache:
php artisan config:clear php artisan cache:clear php artisan optimize:clear
5 إعادة بناء Autoload:
composer dump-autoload

الطريقة 2: التثبيت اليدوي

1 إضافة في composer.json في قسم require:
"utd/area-manager": "*"
2 إضافة في composer.json في قسم repositories:
{ "type": "path", "url": "packages/Utd/AreaManager", "options": { "symlink": true } }
3 تثبيت Dependencies:
composer install --no-interaction
4 تسجيل في PackageHelper:

أضف في app/Support/PackageHelper.php

use Utd\AreaManager\Entities\AreaManager; private static array $packages = [ 'areaManager' => AreaManager::class, ];
5 تشغيل Migrations ومسح الـ Cache:
php artisan migrate php artisan optimize:clear

✅ التحقق من التثبيت:

# التحقق من تثبيت الحزمة composer show utd/area-manager # التحقق من Routes php artisan route:list | grep -i "area" # التحقق من PackageHelper php artisan tinker PackageHelper::isInstalled('areaManager')

إذا كانت النتيجة true فالحزمة مثبتة بنجاح

🗑️ خطوات الإزالة (بدون حذف البيانات)

⚠️ تحذير مهم:

الخطوات التالية تزيل الحزمة من التطبيق ولكن تحتفظ بالبيانات والملفات

  • ✅ البيانات في قاعدة البيانات تبقى محفوظة
  • ✅ ملفات الحزمة في packages/Utd/AreaManager/ تبقى محفوظة
  • ✅ يمكن إعادة التثبيت في أي وقت

الطريقة 1: باستخدام Composer (الموصى بها)

1 حذف من PackageHelper (في app/Support/PackageHelper.php):
// احذف هذا السطر: 'areaManager' => AreaManager::class,
2 إزالة الحزمة عبر Composer:
composer remove utd/area-manager

هذا الأمر يزيل الحزمة من vendor/ ولكن يبقي الملفات في packages/

3 حذف ملفات الـ Cache:
rm -f bootstrap/cache/services.php rm -f bootstrap/cache/packages.php rm -f bootstrap/cache/config.php
4 مسح الـ Cache وإعادة البناء:
composer dump-autoload php artisan config:clear php artisan cache:clear php artisan optimize:clear

الطريقة 2: الإزالة اليدوية

1 حذف من PackageHelper:

احذف من app/Support/PackageHelper.php

'areaManager' => AreaManager::class,
2 حذف من composer.json من قسم require:
// احذف هذا السطر: "utd/area-manager": "*"
3 حذف من composer.json من قسم repositories:
// احذف هذا القسم: { "type": "path", "url": "packages/Utd/AreaManager", "options": { "symlink": true } }
4 تحديث Composer:
composer install --no-interaction composer dump-autoload

✅ التحقق من الإزالة:

composer show utd/area-manager # النتيجة: Package "utd/area-manager" not found php artisan tinker PackageHelper::isInstalled('areaManager') # النتيجة: false

📁 الملفات المحفوظة بعد الإزالة:

  • مجلد الحزمة: packages/Utd/AreaManager/ (كامل)
  • الجداول: regions, region_countries, sub_area_managers, admin_users (WHERE type='area-manager')
  • الـ Relations: محمية في app/Models/Charge.php بـ PackageHelper::checkRelation()
  • Config: أي ملفات configuration تم نشرها

🛡️ العلاقات المحمية (PackageHelper Guards)

جميع علاقات النماذج التي تشير للحزمة محمية بـ PackageHelper، لن تظهر أخطاء إذا كانت الحزمة غير مثبتة:

// في app/Models/Charge.php // ✅ علاقة محمية public function areaManager(): BelongsTo { return PackageHelper::checkRelation($this, 'areaManager', 'belongsTo') ?? $this->belongsTo(AreaManager::class, 'charger_id'); } // ✅ علاقة محمية public function subAreaManager(): BelongsTo { return PackageHelper::checkRelation($this, 'areaManager', 'belongsTo') ?? $this->belongsTo(SubAreaManager::class, 'charger_id'); } // ✅ علاقة محمية public function receiverSubAreaManager(): BelongsTo { return PackageHelper::checkRelation($this, 'areaManager', 'belongsTo') ?? $this->belongsTo(SubAreaManager::class, 'user_id'); }

🔧 استكشاف الأخطاء الشائعة

خطأ: Class "Utd\AreaManager\AreaManagerServiceProvider" not found

الحل:

# 1. حذف ملفات الـ cache rm -f bootstrap/cache/*.php # 2. مسح الـ cache php artisan config:clear php artisan cache:clear php artisan optimize:clear # 3. إعادة بناء autoload composer dump-autoload # 4. التحقق من symlink ls -la vendor/utd/area-manager

خطأ: Routes Not Found (404)

الحل:

# مسح الـ cache وإعادة تحميل الـ routes php artisan optimize:clear php artisan route:list | grep area # التحقق من تثبيت الحزمة composer show utd/area-manager

خطأ: PackageHelper Not Recognizing Package

الحل:

تأكد من تسجيل الحزمة في PackageHelper:

// في app/Support/PackageHelper.php use Utd\AreaManager\Entities\AreaManager; private static array $packages = [ 'areaManager' => AreaManager::class, ];

خطأ: Table 'regions' doesn't exist

الحل:

# تشغيل migrations php artisan migrate # التحقق من حالة الـ migrations php artisan migrate:status

🗄️ جداول قاعدة البيانات

الجداول المستخدمة من قبل الحزمة:

  • admin_users (حقل type = 'area-manager' و type = 'sub-area-manager')
  • regions - المناطق الجغرافية
  • region_countries - ربط المناطق بالدول (pivot table)
  • sub_area_managers - مديري المناطق الفرعيين
