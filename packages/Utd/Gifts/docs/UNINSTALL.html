🗑️ إلغاء تثبيت حزمة الهدايا

Uninstall Gifts Package

⚠️ ملاحظة هامة

إلغاء التثبيت سيؤدي إلى:

  • ❌ إزالة ملفات الحزمة من المشروع
  • ❌ توقف جميع الوظائف المتعلقة بالهدايا
  • ✅ البيانات في قاعدة البيانات ستبقى محفوظة
  • ✅ صور الهدايا ستبقى في مكانها

💡 البيانات لن تُحذف تلقائياً - يمكنك حذفها يدوياً إذا أردت

📦 النسخ الاحتياطي (اختياري)

1. نسخ احتياطي لقاعدة البيانات (إذا أردت)

إذا كنت تريد نسخ البيانات قبل الحذف:

# نسخ الجداول الخاصة بالهدايا mysqldump -u username -p database_name \ gifts \ gift_categories \ gift_logs \ user_gifts \ lucky_gifts \ > gifts_backup_$(date +%Y%m%d).sql

2. نسخ ملفات الصور (إذا أردت)

# نسخ صور الهدايا cp -r public/storage/gifts ~/backup/gifts_images_$(date +%Y%m%d)

🗑️ خطوات إلغاء التثبيت

⚡ إلغاء التثبيت سهل وآمن: أمر واحد فقط لحذف الحزمة!

⚡ الطريقة السريعة (موصى بها)

أمر واحد يكفي لإزالة كل شيء:

composer remove utd/gifts --ignore-platform-req=ext-redis

✅ هذا الأمر سيحذف الحزمة من composer.json و composer.lock تلقائياً

أو اتبع الخطوات اليدوية التالية إذا أردت:

الخطوة 1: حذف الحزمة من composer.json (يدوياً)

افتح ملف composer.json واحذف السطور التالية:

من قسم require:

"utd/gifts": "*"

من قسم repositories:

{ "type": "path", "url": "./packages/Utd/Gifts", "options": { "symlink": true } }

الخطوة 2: إزالة الحزمة عبر Composer (الطريقة الأسهل)

composer remove utd/gifts --ignore-platform-req=ext-redis

💡 ملاحظات مهمة

  • ✅ سيقوم Composer بإزالة الحزمة تلقائياً من composer.json و composer.lock
  • ✅ --ignore-platform-req=ext-redis لتجاهل مشاكل إصدار Redis extension
  • ✅ البيانات في قاعدة البيانات لن تُحذف
  • ✅ قوائم الهدايا ستختفي من Admin Panel تلقائياً
  • ✅ التطبيق سيعمل بشكل طبيعي بدون أخطاء
  • ✅ لا حاجة لتعديل أي كود في التطبيق

بديل: إذا كنت قد حذفت من composer.json يدوياً:

composer update utd/gifts --with-all-dependencies --ignore-platform-req=ext-redis

الخطوة 3: تنظيف الكاش

composer dump-autoload php artisan config:clear php artisan cache:clear php artisan route:clear php artisan view:clear php artisan optimize:clear

الخطوة 4: حذف ملف الإعدادات (اختياري)

إذا أردت حذف ملف إعدادات الحزمة:

rm config/gifts.php

💡 يمكنك الاحتفاظ بالملف إذا كنت تخطط لإعادة التثبيت لاحقاً

الخطوة 5: حذف مجلد الحزمة (اختياري)

إذا أردت حذف مجلد الحزمة من المشروع:

rm -rf packages/Utd/Gifts

⚠️ تحذير: احفظ نسخة احتياطية قبل الحذف إذا كنت تخطط للعودة لاحقاً

الخطوة 6: حذف Class Aliases (نادراً)

إذا كنت قد أنشأت Aliases يدوياً في app/Models:

# فقط إذا كانت موجودة وتريد حذفها rm -f app/Models/Gift.php rm -f app/Models/GiftLog.php rm -f app/Models/GiftCategory.php rm -f app/Models/UserGift.php rm -f app/Models/LuckyGift.php

💡 ملاحظة: معظم المشاريع لا تحتاج هذه الخطوة لأن Models موجودة في الحزمة نفسها

🗄️ حذف البيانات من قاعدة البيانات (اختياري وخطير)

⛔ تحذير شديد: هذه الخطوة اختيارية وخطيرة جداً!

  • ❌ لا تنفذ هذه الخطوة إلا إذا كنت متأكداً 100%
  • ❌ سيتم حذف جميع سجلات الهدايا بشكل نهائي
  • ❌ لا يمكن استرجاع البيانات بعد الحذف
  • ✅ إلغاء التثبيت لا يتطلب حذف البيانات
  • ✅ يمكنك إعادة التثبيت لاحقاً والاستفادة من البيانات الموجودة

💡 نصيحة: احتفظ بالبيانات إلا إذا كنت متأكداً أنك لن تحتاجها أبداً

إذا قررت حذف البيانات (بعد التأكد):

الطريقة 1: استخدام Rollback (الأكثر أماناً):

# سيحذف الجداول بترتيب آمن مع مراعاة Foreign Keys php artisan migrate:rollback --path=packages/Utd/Gifts/Database/Migrations

✅ هذه الطريقة تحترم Foreign Keys وتحذف الجداول بالترتيب الصحيح

الطريقة 2: حذف مباشر عبر SQL:

# احذف الجداول بالترتيب (Foreign Keys أولاً) DROP TABLE IF EXISTS `gift_logs`; DROP TABLE IF EXISTS `user_gifts`; DROP TABLE IF EXISTS `lucky_gifts`; DROP TABLE IF EXISTS `gifts`; DROP TABLE IF EXISTS `gift_categories`;

⚠️ انتبه: تأكد من حذف الجداول بهذا الترتيب لتجنب أخطاء Foreign Keys

حذف صور الهدايا (اختياري):

⚠️ تحذير

تأكد من نسخ الصور احتياطياً قبل الحذف إذا كنت قد تحتاجها لاحقاً

# حذف صور الهدايا rm -rf public/storage/gifts rm -rf storage/app/public/gifts rm -rf storage/app/gifts

💾 الحجم التقريبي للبيانات

قبل الحذف، تحقق من حجم البيانات:

# حجم صور الهدايا du -sh public/storage/gifts du -sh storage/app/public/gifts # عدد السجلات في كل جدول mysql -u username -p database_name -e " SELECT 'gifts' AS table_name, COUNT(*) AS count FROM gifts UNION SELECT 'gift_logs', COUNT(*) FROM gift_logs UNION SELECT 'user_gifts', COUNT(*) FROM user_gifts;"

✨ ماذا يحدث بعد إلغاء التثبيت؟

🎯 النظام مصمم ليكون fail-safe ومتوافق تماماً:

  • ✅ البيانات محمية: لن يتم حذف أي بيانات من قاعدة البيانات تلقائياً
  • ✅ القوائم تختفي: قوائم الهدايا في Admin Panel ستختفي تلقائياً
  • ✅ استخدام Contracts: الباكيجات الأخرى تستخدم GiftServiceInterface وليس الحزمة مباشرة
  • ✅ Null Object Pattern: FeatureServiceProvider يوفر NullGiftService تلقائياً
  • ✅ لا أخطاء: التطبيق يعمل بشكل طبيعي، فقط ميزات الهدايا تتوقف
  • ✅ سهولة الإرجاع: يمكنك إعادة التثبيت بسهولة مع الاحتفاظ بكل البيانات

💡 باختصار:

يمكنك حذف الحزمة مباشرة بدون أي تعديلات على الكود!
النظام سيستمر في العمل بشكل طبيعي، وستبقى البيانات محفوظة،
وقوائم الهدايا ستختفي من Admin Panel تلقائياً.

✅ التحقق من نجاح إلغاء التثبيت

📋 قائمة التحقق النهائية

  • ✔️ تم حذف "utd/gifts": "*" من قسم require في composer.json
  • ✔️ تم حذف repository الخاص بالحزمة من قسم repositories في composer.json
  • ✔️ تم تشغيل composer update بنجاح بدون أخطاء
  • ✔️ تم تنظيف جميع أنواع الكاش (config, cache, route, view, optimize)
  • ✔️ التطبيق يعمل بدون أخطاء عند التشغيل
  • ✔️ لا توجد رسائل خطأ عند زيارة الصفحات المختلفة
  • ✔️ البيانات في قاعدة البيانات لا تزال محفوظة (إلا إذا حذفتها يدوياً)
  • ✔️ تم حذف config/gifts.php (اختياري)
  • ✔️ تم حذف مجلد packages/Utd/Gifts (اختياري)

🧪 اختبار شامل للتطبيق

قم بتشغيل هذه الأوامر للتأكد من عمل كل شيء بشكل صحيح:

# 1. التأكد من عدم وجود أخطاء في الإعدادات php artisan config:cache # 2. التأكد من عدم وجود مشاكل في Autoloading composer dump-autoload # 3. اختبار تشغيل التطبيق php artisan serve # 4. فحص الـ Routes (يجب أن يعمل بدون أخطاء) php artisan route:list # 5. فحص الـ Migrations (للتأكد من عدم وجود migrations معلقة) php artisan migrate:status

💡 ما المتوقع؟

  • ✅ لا يجب أن تظهر أي أخطاء من نوع Class not found
  • ✅ التطبيق يعمل بشكل طبيعي كامل
  • ✅ Routes الخاصة بالهدايا لن تكون موجودة (وهذا طبيعي)
  • ✅ الباقات الأخرى (Room, Moments, Reals) تعمل بشكل طبيعي
  • ✅ أي استدعاء لـ GiftServiceInterface سيستخدم NullGiftService تلقائياً

🔍 التحقق من composer.lock

تأكد من أن الحزمة تم حذفها بالكامل:

# البحث عن الحزمة في composer.lock grep -i "utd/gifts" composer.lock # يجب أن لا يظهر أي نتائج، أو يجب أن تظهر رسالة: # (no matches found)

🔄 إعادة تثبيت الحزمة (استرجاع)

💡 هل تريد إعادة تثبيت الحزمة؟

إذا قمت بإلغاء التثبيت ثم غيرت رأيك، يمكنك إعادة التثبيت بسهولة:

الخطوة 2: إعادة إضافة الحزمة لـ composer (الطريقة السريعة)

# إعادة تثبيت الحزمة بأمر واحد composer require utd/gifts --ignore-platform-req=ext-redis # نشر ملف الإعدادات php artisan vendor:publish --tag=gifts-config --force # تشغيل Migrations (إذا لم تكن موجودة) php artisan migrate # تنظيف الكاش php artisan config:cache php artisan optimize:clear

✅ بعد إعادة التثبيت: قوائم الهدايا ستظهر في Admin Panel تلقائياً!

الطريقة اليدوية: إضافة لـ composer.json

أو أضف السطور التالية يدوياً ثم نفذ composer install:

في قسم require:

"utd/gifts": "*"

في قسم repositories:

{ "type": "path", "url": "./packages/Utd/Gifts", "options": { "symlink": true } }

ثم نفذ:

composer install --ignore-platform-req=ext-redis php artisan vendor:publish --tag=gifts-config --force php artisan migrate php artisan config:cache

استرجاع النسخة الاحتياطية (إذا كنت قد حذفت البيانات)

⚠️ فقط إذا كنت قد حذفت جداول قاعدة البيانات

# استرجاع قاعدة البيانات من النسخة الاحتياطية mysql -u username -p database_name < gifts_backup_20260204.sql # استرجاع صور الهدايا cp -r ~/backup/gifts_images_20260204/* public/storage/gifts/ cp -r ~/backup/gifts_images_20260204/* storage/app/public/gifts/

✅ ميزة حفظ البيانات

إذا لم تحذف جداول قاعدة البيانات:

  • ✅ جميع الهدايا السابقة ستكون متاحة فوراً
  • ✅ سجلات الهدايا المُرسلة محفوظة
  • ✅ صور الهدايا لا تزال موجودة
  • ✅ لا حاجة لإعادة إدخال أي بيانات!

💡 هذا هو السبب في عدم حذف البيانات افتراضياً!

❗ المشاكل الشائعة والحلول

مشكلة 1: Class 'Utd\Gifts\...' not found

السبب: الكاش لم يتم تنظيفه بعد إلغاء التثبيت

الحل:

composer dump-autoload php artisan config:clear php artisan cache:clear php artisan optimize:clear php artisan route:clear php artisan view:clear

مشكلة 2: Routes الخاصة بالهدايا لا تزال موجودة

السبب: Route cache لم يتم مسحه

الحل:

php artisan route:clear php artisan route:cache

مشكلة 3: composer update لا يحذف الحزمة

السبب: الحزمة لا تزال في composer.json أو مطلوبة من حزمة أخرى

الحل:

# 1. تأكد من حذفها من composer.json (require & repositories) # 2. جرّب إزالتها بالقوة composer remove utd/gifts --with-all-dependencies # 3. إذا استمرت المشكلة، احذف composer.lock وأعد التثبيت rm composer.lock composer install

مشكلة 4: أريد حذف البيانات ولكن توجد Foreign Keys

السبب: جداول أخرى تعتمد على جداول الهدايا

الحل:

# احذف الجداول بالترتيب الصحيح (من الأكثر اعتمادية للأقل) SET FOREIGN_KEY_CHECKS=0; DROP TABLE IF EXISTS `gift_logs`; DROP TABLE IF EXISTS `user_gifts`; DROP TABLE IF EXISTS `lucky_gifts`; DROP TABLE IF EXISTS `gifts`; DROP TABLE IF EXISTS `gift_categories`; SET FOREIGN_KEY_CHECKS=1;

⚠️ انتبه: هذا الأمر يُعطّل فحص Foreign Keys مؤقتاً - استخدمه بحذر!

مشكلة 5: Config file لم يُحذف تلقائياً

السبب: Laravel لا يحذف ملفات الإعدادات المنشورة تلقائياً

الحل:

# احذف الملف يدوياً rm config/gifts.php # نظف الكاش php artisan config:clear

مشكلة 6: ظهور أخطاء في Logs بعد إلغاء التثبيت

السبب: بعض الباقات تحاول استدعاء Gift Service

الحل:

✅ لا حاجة للقلق! هذا طبيعي في الفترة الانتقالية:

  • النظام يستخدم NullGiftService تلقائياً
  • الأخطاء ستختفي بعد تنظيف الكاش
  • قم بتنظيف الـ Logs القديمة:
php artisan log:clear # أو يدوياً rm storage/logs/laravel-*.log
