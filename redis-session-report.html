تقرير: مشكلة سقوط السيرفر بعد تغيير SESSION_DRIVER=redis

Branch: redis-session-config  |  التاريخ: 2026-04-26

المشكلة

بعد تغيير SESSION_DRIVER من file لـ redis في ملف .env، السيرفر بيقع بشكل متقطع (intermittent crashes) وبيرجع Error 500 على كل الريكويستات.

تحليل أسباب المشكلة

1. عدم وجود Timeout على Redis Connections

الكونفيجريشن القديمة مكانش فيها أي timeout أو read_timeout. لما Redis يبطئ لأي سبب (ضغط على الرام، slow query، network lag)، التالي بيحصل:

Redis slow/unresponsive
↓
Every request opens connection & waits (30-60s TCP timeout)
↓
Requests pile up behind each other
↓
All PHP workers become busy (hanging)
↓
No free worker to serve new requests
↓
SERVER DOWN

2. السيشنات والكاش على نفس الـ Redis Database

مكانش فيه كونكشن مخصصة للسيشن، فكان بيستخدم الـ default connection على database 0. ده بيسبب:

  • أمر cache:clear ممكن يمسح سيشنات اليوزرز ويعملهم logout
  • لو Redis عمل eviction بسبب ضغط على الذاكرة، ممكن يمسح سيشنات

3. الفرق بين الكاش والسيشن لما Redis يقع

الكاش (Cache) السيشن (Session)
لما Redis يقع الأبليكيشن تكمل عادي OK كل ريكوست يرجع 500 FATAL
السبب الكاش optional - يتجاهله ويكمل السيشن middleware بيشتغل على كل ريكوست ولازم ينجح
التأثير بطء مؤقت فقط سقوط كامل للسيرفر

الحل اللي اتعمل

1. إضافة Timeout على كل Redis Connections

config/database.php

تم إضافة timeout على كل الكونكشنز عشان لو Redis بطئ، الريكوست يفشل بسرعة (2 ثانية) والـ worker يتحرر يخدم ريكويستات تانية.

'read_timeout' => 2.0,   // لو Redis بطيء في الرد، يقطع بعد 2 ثانية
'timeout' => 2.0,        // لو مش بيرد أصلاً، يفشل بعد 2 ثانية
'retry_after' => 5000,   // يحاول تاني بعد 5 ثواني

2. كونكشن Redis مخصصة للسيشن على Database منفصلة

config/database.php

تم إضافة كونكشن جديدة اسمها session على Redis database رقم 2 عشان نفصل السيشنات عن الكاش تماماً.

'session' => [
    'url'          => env('REDIS_URL'),
    'host'         => env('REDIS_HOST', '127.0.0.1'),
    'password'     => env('REDIS_PASSWORD', null),
    'port'         => env('REDIS_PORT', '6379'),
    'database'     => env('REDIS_SESSION_DB', '2'),
    'read_timeout' => 2.0,
    'timeout'      => 2.0,
],
توزيع الـ Redis Databases:
DatabaseالاستخدامENV Variable
0Default (عام)REDIS_DB
1CacheREDIS_CACHE_DB
2SessionsREDIS_SESSION_DB

3. ربط السيشن بالكونكشن الجديدة

config/session.php

'connection' => env('SESSION_CONNECTION', 'session'),

المطلوب على السيرفر بعد الـ Deploy

  1. إضافة في ملف .env: 
    SESSION_DRIVER=redis
REDIS_SESSION_DB=2
  2. تنفيذ الأمر التالي: 
    php artisan config:cache

النتيجة المتوقعة

السيناريو قبل OLD بعد NEW
Redis بطئ لحظة Workers معلقة 30-60 ثانية → سقوط يفشل في 2 ثانية → الـ worker يتحرر
تنفيذ cache:clear سيشنات اليوزرز ممكن تتمسح السيشنات مش هتتأثر (database منفصلة)
Redis memory eviction ممكن يمسح سيشنات السيشنات معزولة ومحمية

الملفات اللي اتعدلت

الملفالتعديل

config/session.php تغيير الـ connection الافتراضية لـ session
